# Что изменено ради скорости

Предыдущий пакет был рассчитан на максимальную формальную полноту до реализации. Он содержал более сотни файлов, сотни требований, отдельные схемы, ADR, traceability и несколько CI-контуров. Это повышало стоимость чтения и синхронизации для Codex и провоцировало документационные итерации до появления рабочего вертикального среза.

Fast-track пакет оставляет один источник цели, один план, один набор критериев и один статус. Главное изменение — порядок реализации:

```text
рабочий end-to-end simulator/replay
→ живой public shadow на трёх биржах
→ Telegram + recovery
→ private canary-ready на двух биржах
→ только затем ещё четыре биржи
```

Технические ускорения:

- CCXT Pro за собственным adapter boundary вместо семи native connectors с нуля;
- SQLite WAL вместо раннего PostgreSQL;
- Parquet + DuckDB вместо отдельного аналитического сервиса;
- один modular monolith и Docker Compose;
- один branch/PR вместо PR на каждый формальный слой;
- короткий mutable `STATUS.md` вместо traceability-матрицы;
- 36 конечных критериев вместо сотен атомарных требований;
- sample-based qualification runner вместо ожидания внутри Codex-сессии;
- venue quarantine вместо остановки проекта из-за одной биржи.

Удалённые артефакты можно вернуть после рабочего canary, если появится доказанная необходимость. До этого они не являются частью критического пути.
